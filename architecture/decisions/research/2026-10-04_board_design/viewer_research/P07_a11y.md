# P07 — Accessibility lens: a living board that stays usable by keyboard, screen reader and touch

Panelist P07. Read-only pass on 2026-10-04 over the approved mockups (http://127.0.0.1:8710) and the
board's source (`studio/command_center/`). The live board (http://127.0.0.1:8700) returned **500 on
every page** during this pass because the reskin is mid-way, so every live-board claim below comes from the
templates and `static/progress.js`, not from a running page. The mockup claims were measured with
browse (`shots/panel/p07_*.png`), and the contrast numbers were computed from `static/css/tokens.css`
(script: `scratchpad/p07_contrast.py`).

**Thesis.** "More dynamic" is an accessibility problem before it is a visual one. Every poll that
swaps HTML can take focus away, reset a screen reader's reading position, or announce nothing at all.
Every loop that runs forever is a WCAG 2.2.2 obligation. The board's colours already pass; its
*liveness* does not, yet. Fix the plumbing that announces, morphs and pauses once, in the shell, so that
each new dynamic feature the other panelists add inherits it for free.

## 1. What already passes (keep it)

- **Text contrast passes AA, and mostly AAA, in both themes.** Studio black: ink 16.3, ink-2 9.4, ink-3 6.0,
  accent 5.6, and every state fg ≥ 6.7 on paper; ≥ 4.85 on surface-2. Graphite: ink-3 5.3 and state fg
  5.4–7.3 on paper. The tightest pair is Graphite flagged-on-flagged-bg at **4.84:1**, which still passes.
  `test_tokens_meet_contrast` guards this, so keep it in CI.
- **The focus ring** `--focus` measures 5.9:1 on Studio black paper and 4.4:1 on Graphite paper. Graphite's ring
  on the stage (#121212) is 3.94:1. All of these pass the 3:1 bar of SC 1.4.11 / 2.4.13.
- `:focus-visible` is global (`components.css:23`). Reduced motion kills every animation and transition (`components.css:24`).
- The live card has a deliberate single `aria-live="polite"` on the vital word, and no ticking clock sits in a live
  region (`_live_vital.html:1-8`). That is correct etiquette.
- The rail's list items carry full names ("07 board · running 10 min"), and the progress hero is a real
  `role="progressbar"`.

## 3. The design: one announcer, one morph, one motion switch

**3.1 The announcer (fixes A1, A5, and every future "dynamic" feature).** `base.html` / the shell renders
`<div id="sr-status" class="sr-only" role="status" aria-live="polite" aria-atomic="true"></div>` and
`<div id="sr-alert" class="sr-only" role="alert"></div>` **once**, outside every swapped region, and never
replaces them. A new `static/announce.js` exposes `board.announce(text, {key, urgent})`:
- It **dedupes** by `key`, for example `ep17:step:08`, so the same fact is never spoken twice across polls.
- It **coalesces** messages that arrive within 1.5 s into one sentence ("ep17 moved to 08 panels; Needs you now 6").
- It clears the region, then writes the text after a 100 ms delay, which makes repeat text re-announce reliably.
- Only the terminal events in 09's notification table use `sr-alert`: **dead, refused, stalled**. Done, a step
  change and a needs-you increment are `polite`. Clocks, percentages and trace beats are **never** announced.

The data is already in the JSON twin that `apply()` reads (`prev` vital, `p.vital`, `p.now_step.id`), and the
needs-you count is in `/partials/needs-you-count`. `progress.js` calls `announce` from `apply()` **before** the
`swap()` branch, so a shape change is spoken from the persistent region. The toast keeps its look but stops being
the announcer: it calls `announce()` and stays visible until it is dismissed, or for at least 10 s while
hovered or focused.

**3.2 Morph, not replace (fixes A3, keeps focus and reading position).** Every polled region adopts
[htmx idiomorph](https://htmx.org/extensions/idiomorph/) (`hx-ext="morph"`, `hx-swap="morph:innerHTML"`) and gives
rows stable ids (`id="att-ep12"`). Morphing patches the existing nodes, so a focused button survives as the same node. As a
second line of defence, apply the same `[!document.activeElement.closest('form,dialog,[data-row]')]` guard to
`home.html`'s `#floor` and `#attention`. `progress.js swap()` becomes a morph of `#live` as well
(idiomorph exposes `Idiomorph.morph(card, html)`), which also keeps the live region node alive. While a fetch is in
flight, set `aria-busy="true"` on the region and clear it after the morph.
*How to know it worked:* a browse test focuses `#attention button`, waits 5 s, and asserts
`document.activeElement === saved`. This mirrors the probe I ran in this pass, which could not run against the 500 board.

**3.3 Motion switch (fixes A4, satisfies 2.2.2).** Add a **"Still"** toggle next to the theme toggle. It sets
`data-motion="still"` on `<html>`, is remembered with `localStorage` `cc-motion`, has the same effect as
`prefers-reduced-motion`, and is also on `?` and in the palette ("Pause motion"). CSS gates every loop with
`:root:not([data-motion=still])` inside `@media (prefers-reduced-motion:no-preference)`. A static test greps
the CSS for `infinite` outside that guard. A runtime test asserts `getAnimations().filter(a=>a.effect.getTiming().iterations===Infinity).length <= 1` on every page
([2.2.2](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)).

**3.4 Live-change etiquette (the rules every proposer should follow).**
1. Values update silently. Only **state transitions** speak, one sentence each, in the owner's words:
   "ep17 now 08 panels", "ep17 done, 2 flags", "ep17 stalled: no sign for 6 min".
2. The "Since 14:02" activity feed becomes `role="log"` with `aria-relevant="additions"`
   ([MDN log role](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Roles/log_role)). New rows are
   prepended *without* moving focus or scroll. If the user has scrolled the feed, a "3 new" pill appears instead
   of the list scrolling itself.
3. The page never steals focus because of a poll. Focus moves only as the result of a user action.
4. Colour is never the only carrier. Every state dot and every rail or tile state also has a word or glyph, in the
   accessible name and on screen (✓, ✕, r2, the state word).
5. Favicon and `document.title` updates are good for sighted users who are in another tab. They are not
   announcements, so they never stand in for the announcer.

## 4. Smaller fixes

- **A2:** `patchHero` writes `hero.setAttribute('aria-valuetext', p.live_valuetext)`. The server already
  computes `live_valuetext`, so add it to the JSON twin. For a non-counted step, drop `role=progressbar`
  and use plain text, because a progressbar stuck at 0/1 is a false statement.
- **A6:** make the "view" button a sibling that is positioned over the card (`.pic` becomes a `div` holding `<a>` plus `<button>`),
  following the stretched-link pattern, not nesting.
- **A7:** add `<a class="skip" href="#main">Skip to content</a>` as the first child of `<body>`, plus `<main id="main" tabindex="-1">`.
  `G`-chord navigation also focuses `#main`.
- **A8:** use `<span class="sr-only">, 1 running, 5 flagged</span>` inside the link, give the dots `aria-hidden`, and add the count
  "31 units" in sr text.
- **A9:** the keysheet gets a "Single-key shortcuts: on/off" switch (`cc-keys`). Chords stay, and Ctrl/⌘K always works
  ([2.1.4](https://www.w3.org/WAI/WCAG22/Understanding/character-key-shortcuts.html)).
- **A10:** add a token `--ctl-line`. Studio black **#6b6f78** (3.78:1 on paper, 3.28:1 on surface-2); Graphite
  **#7a808a** (3.64:1 on paper, 3.98:1 on white). Use it for input, `.btn` and waiting-segment borders. Decorative
  dividers keep `--rule`. Extend `test_tokens_meet_contrast` with the 3:1 non-text pairs
  ([1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)).
- **A11:** set `min-block-size:24px` on `.chipnum`, `.uid`, `.shotchip`, `.gchip`, `.lv-notify` and `.btn`. Under
  `@media (pointer:coarse)` raise it to 44 px, using padding or a `::after` hit area so the dense desktop look is unchanged.
- **A12:** `html{scroll-padding-top:var(--ph-h); scroll-padding-bottom:64px}` on phone, so a focused row is never under
  the sticky bars ([2.4.11](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)).
- The notify button becomes a toggle with `aria-pressed`, and its label stays "Notify me".

## 5. How to verify, at $0

Each pass runs a browse script per page in both themes, and in reduced-motion emulation:
- a Tab walk: the first stop is the skip link, and the focus ring is visible at each stop (screenshot);
- a focus-survives-poll probe, as in 3.2;
- an `getAnimations()` loop count of 1 or fewer;
- `document.querySelectorAll('a button,button a').length === 0`;
- a target-size sweep (the JS from this pass) that reports 0 standalone targets under 24 px.

For speech, one manual NVDA + Chrome session per release, listening across a step change on ep17 for the
sentence "now 08 panels". A pytest that asserts `#sr-status` exists exactly once in the rendered shell and appears in no partial.

## I will argue against

1. **Toasts as the "it updated" signal.** Expect proposals like "toast when a step lands / a unit finishes".
   A toast disappears after a few seconds, so a person who looks away misses it. It renders under any open `<dialog>` backdrop (V08 F6).
   As implemented, it is not announced (A5). The durable home for change is the "Since …" log, plus the badge, plus one
   spoken sentence. A toast may echo an action the owner just took, but never a background change.
2. **Faster or push liveness: 1 s polls, SSE, rolling-digit counters, animated row re-sorting.** Each one adds
   churn that a screen reader re-reads, motion that triggers vestibular problems, and focus loss whenever a row moves. 09_liveness_motion
   already ruled no SSE, a 2 s poll and pulse+morph, and I hold that line. "More dynamic" should mean *more accurate
   and better announced*, not more frequent and more animated. Rows never reorder under the cursor. A re-sort waits
   until focus leaves the list, or for an explicit "Sort" action.
3. **Hover-only richness: video-on-hover, actions revealed on hover, tooltips that carry data.** One owner on
   a phone has no hover, and keyboard focus must reveal the same thing (`.has-xp:focus-within` already does). Any
   proposal whose information lives only in `title=` or `:hover` must also show it on focus or tap, or put it in the visible text.
   Also, dimming text for "moodier" dark aesthetics: `--ink-3` at 6.0:1 is the floor, not slack to spend.
